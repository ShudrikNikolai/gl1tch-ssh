## О проекте

`gl1tch-ssh` — это шлюз, который превращает SSH-подключение в чат. Никаких паролей и веб-интерфейсов: пользователь подключается по SSH-ключу, при первом входе выбирает ник, после чего может создавать комнаты, приглашать участников по токену и обмениваться сообщениями.

## Возможности

- **Аутентификация по SSH-ключу** — идентификация по SHA256-fingerprint публичного ключа, без паролей.
- **Авто-регистрация** — при первом подключении ник выбирается интерактивно и фиксируется навсегда.
- **Комнаты до 4 участников** — создание, вход по токену, бан участников хостом.
- **История сообщений** — последние 20 сообщений при входе и по `@chat /prev-msg`; keyset-пагинация заложена в репозитории.
- **Redis Pub/Sub** — broadcast сообщений между инстансами через `RedisBroadcaster`, готовность к работе за HAProxy.

## Архитектура

Модульный монолит с hexagonal-подходом к ядру: транспорт (SSH) не знает о домене, домен не знает о Postgres.

```
cmd/ssh/                          — точка входа
internal/
  app/                            — сборка приложения, DI-контейнер
  infrastructure/
    config/                       — конфигурация из env
    logger/                       — slog
    pg/                           — pgxpool + миграции (goose)
    redis/                        — клиент + RedisBroadcaster (Pub/Sub)
  modules/
    aggregate/                    — сквозные сценарии через несколько модулей
    chats/                        — домен комнат: repository / service
    messages/                     — домен сообщений: repository / service
    users/                        — домен пользователей: repository / service
  transport/                      — SSH-сервер, парсинг команд, обработчики
deploy/                           — docker-compose (Postgres, Redis)
```

## Быстрый старт

### Требования

- Go 1.26+
- Docker + Docker Compose
- SSH-клиент

### Запуск

```bash
# 1. Клонировать
git clone https://github.com/ShudrikNikolai/gl1tch-ssh.git
cd gl1tch-ssh

# 2. Поднять зависимости
task deploy:up          # или: docker compose -f deploy/docker-compose.yaml up -d

# 3. Запустить сервер (миграции применяются автоматически)
task run                # или: go run ./cmd/ssh
```

Если БД создана не через compose, примените миграции вручную: `task migrate:up`.

Сервер слушает `:2222`. Подключение:

```bash
ssh -p 2222 localhost
```

При первом подключении сервер сгенерирует временный host-key и попросит выбрать ник.

### Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

```bash
cp .env.example .env
```

## Конфигурация

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ENV` | `dev` | Окружение в логах |
| `LOG_FORMAT` | `text` | `text` или `json` |
| `SSH_ADDR` | `:2222` | Полный адрес прослушивания SSH (с двоеточием) |
| `SSH_HOST_KEY_PATH` | — | Путь к приватному host-key (если пусто — генерируется временный) |
| `SHUTDOWN_TIMEOUT` | `10s` | Таймаут graceful shutdown |
| `PG_DSN` | — | DSN PostgreSQL, обязателен |
| `REDIS_ADDR` | `localhost:6379` | Адрес Redis |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `CHAT_MAX_MEMBERS` | `4` | Лимит участников комнаты |
| `MESSAGE_MAX_RUNES` | `300` | Лимит длины сообщения |
| `NICK_MAX_LEN` | `18` | Лимит длины ника |

## Команды

### Общие

| Команда | Описание |
|---|---|
| `/whoami` | Показать свой ник |
| `/chats-list` | Список чатов, в которых вы состоите |
| `/chats-create` | Создать комнату, вернуть токен приглашения |
| `/chats-join <token>` | Войти в комнату по токену |
| `/chats-delete` | Удалить текущую комнату (только host) |

### Внутри комнаты

Команды с префиксом `@chat` выполняются в контексте текущей комнаты:

| Команда | Описание |
|---|---|
| `@chat /send <text>` | Отправить сообщение (до 300 рун) |
| `@chat /prev-msg` | Последние 20 сообщений |
| `@chat /ban <nickname>` | Забанить участника (только host) |

Если вы не в комнате и пытаетесь выполнить `@chat`-команду — соединение будет закрыто.
